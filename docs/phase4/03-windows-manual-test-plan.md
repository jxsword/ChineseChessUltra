# 第四阶段 Windows 平台手动测试设计方案

> 适用版本：第四期（棋谱库 + 残局工作室 + AI 求破解）功能验收。
> 测试角色：无编程背景的人工测试者即可执行；涉及大模型的用例需自备 API Key（仅录入应用界面，不写入任何文件）。

## 1. 测试目标与范围

### 1.1 目标

1. 验证四期新功能在 Windows 上的**功能正确性**：棋谱保存/重放/导出、残局摆盘/FEN 导入/图片识图、AI 求解四种结论（唯一解/多解/无解/超时）。
2. 验证**数据可靠性**：棋谱持久化、旧数据库升级迁移、与既有自动存档互不干扰、重启后数据完好。
3. 验证**异常与边界**：非法 FEN、无网络、错误 Key、识图失败降级等路径不崩溃、有明确提示。
4. 对三期"大模型对战"做**回归**（本期在其配置存储中新增了槽位）。

### 1.2 需求追溯矩阵

| 原始需求（四期任务书） | 对应测试模块 | 关键用例 |
|---|---|---|
| 保存当前棋局为棋谱（含走法历史） | A | TC-REC-001~008 |
| 棋谱便于后期研究或分享 | B/C | TC-LIB-001~009, TC-DET-001~005 |
| 自己摆残局 | D | TC-SET-001~007 |
| 导入棋局（FEN） | E | TC-FEN-001~005 |
| AI 识图转换坐标，人工校正 | F | TC-VIS-001~007 |
| AI 求解、判断唯一性、枚举所有破解之法 | G | TC-SOL-001~006 |
| 无解/超时单独标记，但仍持久化为棋谱 | G/H | TC-SOL-005/006, TC-PER-002 |
| 大模型提示词方案集成（Hybrid） | G | TC-SOL-007/008 |
| 旧数据兼容 | H | TC-PER-001~004 |
| 不破坏三期功能 | I | TC-REG-001~003 |

## 2. 测试环境与准备

### 2.1 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 21H2 及以上 / Windows 11（主测 1920×1080、缩放 100%；另抽测 125%/150% DPI） |
| 构建 | 开发机：`flutter run -d windows`；验收建议：`flutter build windows` 后运行 `build/windows/x64/runner/Release/chinese_chess_ultra.exe` |
| 网络 | 分两组执行：联网组（识图/大模型用例）与离线组（TC-EXC-003） |
| 数据目录 | `%USERPROFILE%\Documents\chinese_chess_ultra.sqlite`（棋谱与存档数据库） |

### 2.2 测试前准备清单

1. **准备一份"旧版本数据"**（用于 TC-PER-001）：检出上一期代码（git log 找四期之前的提交）运行一局双人棋并保存退出，生成的 sqlite 文件备份；或使用任一历史版本用户的真实数据库副本。
2. **准备测试用视觉模型配置**：在应用"残局工作室 → 研究助手模型配置"中录入端点与 Key（例如智谱 GLM 端点 + 视觉模型 ID）。Key 只进系统安全存储；若没有可用的视觉模型，F 模块中标注 [视觉] 的用例记"阻塞"而不是"失败"。
3. **准备棋盘图片素材**：
   - 素材 A：本应用截图（在对局页按 `Win+Shift+S` 截取棋盘区域）——识别成功率最高；
   - 素材 B：任意象棋 App/网站的俯拍正视角棋盘图（残局，非开局）；
   - 素材 C：一张斜 45° 拍摄的真实棋盘照片（预期可能识别错误，用于验证人工校正与兜底）。
4. 每轮测试开始前**记录数据库文件大小与棋谱条数**（棋谱库页面计数），便于持久化用例核对。

## 4. 执行顺序与冒烟清单

### 4.1 建议执行顺序

1. TC-PER-001（旧库迁移，需要旧数据，先做避免被新数据污染）
2. A → B → C（棋谱主线）
3. D → E → G（摆盘/FEN → 求解主线）
4. F（识图，依赖模型配置与网络）
5. H 其余 → I → J

### 4.2 30 分钟冒烟清单（版本准入）

- [ ] TC-REC-002（保存棋谱）
- [ ] TC-LIB-001 / TC-DET-001（列表与重放）
- [ ] TC-SET-002（摆盘子）
- [ ] TC-FEN-001（FEN 导入）
- [ ] TC-SOL-001 / TC-SOL-002（多解求解 + 自动入库）

- 全部 P0 用例通过；
- P1 用例通过率 ≥ 95%，失败项均有缺陷记录且无数据丢失类缺陷；
- P2 用例无"崩溃/数据丢失"级别问题；
- 已知限制（不计缺陷）：FEN-C 求解用时因机器而异；斜拍照片识图准确率依赖模型；长将判负为近似处理。
