## B. 确定性能力检验（无网络、CI 可跑、可重复）

原理：用"**确定性弱模型**"（解析 prompt 中的着法清单，按固定策略选尾/选首的脚本化 HTTP 假客户端）替代真实模型，消除随机性；引擎侧用固定深度搜索，结果完全可复现。

| 用例 | 断言 | 检验点 |
|---|---|---|
| B1 战术命中率 | 3 个战术局面（吃车/双车杀/中线），候选模式命中引擎 Top-3 = 3/3；基线"选尾"严格更低 | P1 是否把模型"关进好棋笼子" |
| B2 对局质量 | 短局（40 手）vs ChessAi(d1)：Hybrid 失误数（逐手引擎分差 >250 厘兵）≤ 基线 | P1 是否降低实战送子率 |
| B3 大模型对战场景 | 候选 vs 护航互打 30 手：正常终局、棋谱可追溯 | 两种模式共存对抗的稳定性 |
| B4 护航否决链 | 亏着 → 否决 → 再问 → 采纳；双否决 → 引擎代走；note 如实记录 | 底线兜底是否可靠 |

## C. 真实模型对抗赛（本地执行，密钥走环境变量）

配置：qwen3.8-max（与用户当前实际使用一致），`enable_thinking:false`（对弈通道默认）。

| 局 | 红方 | 黑方 | 限制 | 检验 |
|---|---|---|---|---|
| C1 | 基线 v1 | ChessAi(d2) | 36 手上限，逐手质量评估 | 基线失误率 |
| C2 | P0（v2 prompt） | ChessAi(d2) | 同上 | Prompt v2 单独收益 |
| C3 | Hybrid 候选(blend 50, 深度4) | ChessAi(d2) | 同上 | 参谋名单收益 |
| C4 | Hybrid 护航(blend 50, 深度4) | ChessAi(d2) | 同上 | 否决权收益 |
| C5 | Hybrid 候选 | Hybrid 护航 | 30 手上限 | "大模型对战"场景稳定性 |

指标：胜负（winner）、手数、每手均耗时、**失误率**（分差>250 厘兵手数 / 评估手数）、兜底率（fromFallback 占比）、非法手。对比 C1→C4 的失误率曲线即为"能力提高程度"的量化结论；B 段为不受模型随机性影响的下界证明。

## D. 结论判据

1. A1/A2 全绿 → 实现无回归；
2. B1：候选命中率 100% 且 > 基线 → 参谋约束生效；
3. B2：Hybrid 失误数 ≤ 基线 → 参谋制对弱模型有正收益（下界）；
4. C 段：真实模型失误率随 P0→P1 递减、护航无"致命"级失误 → 达成"提高下棋能力"目标；
5. 任一 D 判据不满足 → 记录并回归修复。
